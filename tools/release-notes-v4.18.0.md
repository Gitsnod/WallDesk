# WallDesk v4.18.0 — 状态栏直达、下拉框归位、文档分流

底部状态栏现在常驻显示分辨率、帧率、CPU 与内存，不用再把鼠标停在上面等浮层；
下拉框和「更多」终于看得出是能点开的；README 按人来分了，只想用的人不会被构建步骤拦住。

## 新增

- **状态栏常驻性能信息**：`3840×2160 · 24.0 fps · CPU 0.2% · 内存 856 MB`，每 2 秒刷新。
  CPU 是「占整机」口径（与任务管理器一致），多线程解码时不会看到超过 100% 的数。
  完整参数（解码档位、下发参数、缩略图缓存、内存峰值、运行时长）仍在悬停提示里。
- **开发者文档独立**：`docs/DEVELOPER.md`，环境清单、构建、调试、打包、发版通道、
  目录结构、设计要点都在那里。

## 变更

- **README 面向使用者重写**：GitHub 首页看到的是「是什么 / 怎么下载 / 第一次用 / 功能 /
  参数 / 常见问题」，构建与发版内容移出。原文 351 行，逐节标注去向，专有名词 grep 复核无遗漏。
- **状态胶囊去掉悬浮详情浮层**：那个「停 200ms 才弹、移开就收」的浮层删掉了，
  信息改为常驻。

## 修复

- **帧率一直是 0**。`libvlc_media_player_get_fps` 返回的是 `float`，函数指针却按 `double`
  声明。float 的 32 位位模式被当成 double 的低半部分，读出来约 `1e-314`，调用方一律判为
  「无帧率」。改成按 `float` 接收后，4K@24fps 视频实测显示 `24.0 fps`。
- **视频壁纸的分辨率永远显示「—」**。`MediaInfoProbe` 走 `QImageReader`，只认图片；
  视频改为向 libVLC 要 `libvlc_video_get_width/height`，图片仍走原路径。
- **下拉框不像下拉框**。QSS 里 `::drop-down` 只给了宽度、从没定义 `::down-arrow`，
  右侧 18px 是空白，整个控件看着就是个输入框。改为自绘 chevron，悬停转主色。
- **「更多」看不出带菜单**。按钮全自绘背景后，Qt 不再画 `menu-indicator`，
  只剩「更多」两个字。在 sizeHint 已预留的右侧空间补画 chevron。
- **状态栏出现「— — fps」**。分辨率与帧率各写一个占位符，两个破折号挨在一起。
  改成合并成一个「播放」字段，都拿不到时只显示一个「—」。

## 已知

- 状态栏信息随窗口变窄不会省略，极窄窗口下会挤压左侧的临时消息。默认 1100px 以上无影响。
- 空状态、滑块数值显示这两项仍按 v4.17.0 的口径未处理。

## 校验

- `tools/check_sources.py`、`tools/check_changelog.py`：K1–K10 全部通过
  （其中 K10 要求每个版本都有对应 git tag，打完 tag 后成立）。
- 状态栏取值为实际播放画面：4K MP4 播放中读到 `3840×2160` 与 `24.0 fps`，
  CPU 0.2%–1.0%（随解码波动），内存在 833–856 MB 之间。
- 下拉框与「更多」的箭头：截图核对，四处下拉 + 五个设置页下拉 + 操作行按钮均已出现。
