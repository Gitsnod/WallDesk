# 视频壁纸软件竞品对比与 WallDesk 升级计划

- 日期：2026-10-21
- 对象：Windows 桌面视频 / 动态壁纸软件
- 基线：WallDesk 4.8.0（本仓库当前版本）

---

## 0. 结论摘要

1. **市场分两层**：付费标杆 Wallpaper Engine（¥22.90，Steam 中国区实测）靠「编辑器 + Steam 创意工坊」筑墙；开源阵营 Lively（19.9k star）靠「格式全 + 智能暂停 + 免费」抢人。
2. **WallDesk 不在"内容生态"这条赛道上，也赢不了**：它的真实差异点是「原生 C++ / 单 exe / 内嵌 VLC / 便携免装 / 整套桌面状态预设」。
3. **最该补的不是新格式，是"资源控制颗粒度"**：逐应用暂停规则、帧率与解码档位可见化、播放列表触发条件 —— 这三项 Wallpaper Engine 与 Lively 都有，WallDesk 没有，且成本可控。
4. **网页/着色器壁纸是品类分水岭**，但属于"要么真做、要么不做"的决策，不建议半途投入；建议先做「轻交互」（视差 + 点击事件），把重引擎留给后续版本评估。
5. **明确不做**：自研场景/粒子编辑器、社区运营、移动端伴侣 —— 这三项投入产出不成立。

### 2.1 三条解读

**（1）格式广度不是 WallDesk 的战场。** Lively 一个产品就覆盖 视频 / GIF / 网页 / 着色器 / Unity / Godot / 流媒体 URL 六类；
Wallpaper Engine 用编辑器把这六类"创作化"。WallDesk 只有视频 + 图片，硬追必然落后。

**（2）WallDesk 有两个别人没有的组合。**
- **「整套桌面状态」预设**：一个预设同时打包 壁纸 + 填充方式 + 画面效果 + 桌面挂件 + 切换策略 + 逐屏配置。
  Wallpaper Engine 的播放列表只切壁纸，不管效果与挂件；Lively 也没有等价抽象。
- **「零依赖交付」**：内嵌 VLC + 单 exe + 便携模式。Lively / Sucrose / AwesomeWallpaper 全部是 .NET 栈，
  用户机器上必须有对应的 .NET 运行时；WallDesk 只要 Windows。

**（3）内容生态是最大结构性劣势。** 没有社区就没有"打开就有几百张能用的壁纸"，这会让新用户在前 3 分钟流失。
但自建社区不现实，可行路径是**兼容别人的包**（见 P1-3）。

## 3. UI 与动画交互对比

| 维度 | Wallpaper Engine | Lively | Sucrose | WallDesk 4.8.0 |
|---|---|---|---|---|
| 主界面结构 | 库视图 + 预览区 + 右侧详情/属性 | 库网格 + 控制面板 + 属性面板 | 库 + 引擎/插件管理 | 左侧三页导航（壁纸库 / 设置 / 多屏）+ 画廊 |
| 发现路径 | Workshop 订阅 → 一键应用 | 内置库 + 拖入本地文件 | 社区浏览 + 本地创建 | 本地添加 / 粘贴网址 / Bing 每日一图 |
| 参数调节 | 逐壁纸属性（创作者暴露的控件） | `LivelyProperties`（滑块 / 取色器 / 下拉） | 属性 + 插件 | 12 组设置，按 5 页分组；逐壁纸参数不可配 |
| 编辑器 | ✅ 场景 / 粒子 / SceneScript | ◐（靠外部写 HTML/GLSL） | ◐（创建壁纸，非可视化编辑器） | ✗ |
| 主题 | 深色为主 | 浅 / 深 | 浅 / 深 | 浅 / 深 / 跟随系统 |
| 动效 | 预览卡片、编辑器内实时预览 | 库卡片预览 | 库卡片 | 缩略图悬停/选中态；页面切换无过渡动画 |
| 多屏配置 | 统一设置 | 跨屏 / 逐屏 / 网格三模式 | 多屏支持 | 左侧「多屏」页逐屏指定图片 |

### 3.1 差距判断

- **WallDesk 的导航结构不比对手差**：4.8.0 刚把 12 组设置拆成「左侧二级导航 + 右侧滚动」，信息架构已经接近 Lively 的控制面板。
- **真正落后的是"预览与发现的交互"**：对手都能在卡片上直接看到动态效果（Lively 的 GIF 预览、WE 的视频预览），
  WallDesk 只有静态缩略图 + 播放角标。这是**用户第一眼就能感知的差距**，且实现成本低。
- **动效缺失**：页面切换、抽屉展开、缩略图加载都是硬切。Qt 的 `QPropertyAnimation` 足以补齐，不需要换 UI 框架。

### 4.3 三处硬差距（2026-10-21 首版审计结论；括号内为当日执行后的现状）

1. ~~**逐应用规则完全缺失**~~ → **已补齐**：`src/` 原先 grep `per-app|逐应用` 零命中，只有
   「全屏 / 电池 / 锁屏」三种全局策略；现新增设置 → 播放 → 资源控制，规则按前台进程生效。
2. **解码档位本来就存在，缺的是「可验证」**：`VlcProfile` 四档（自动 / 硬件优先 / 软件 / 高画质）
   早就有，设置页有下拉、配置也会持久化。**本文初版写「设置页没有对应选项」是错的**；
   真正缺的是日志与界面都不回显下发参数，用户无法确认硬解是否生效。现已回显，并补了「省电」档。
3. **没有帧率上限**（仍未解决）：只能靠丢帧被动控负载。libVLC 没有原生限帧选项，要做需要
   自定义 vout 按 PTS 丢帧，成本与风险都高，不在本轮范围。


## 5. WallDesk 的定位与取舍

### 5.1 保留并放大的优势

| 优势 | 证据 | 商业化/传播角度 |
|---|---|---|
| 零依赖交付 | 内嵌 VLC（`src/VlcBundle.bin`），无需装 VLC、无需 .NET | "解压即用"是开源竞品都给不了的 |
| 整套状态预设 | `PresetManager`（`presets.json`，可手改可拷走） | 可包装成"工作/娱乐/夜间"三套桌面模式 |
| 便携 + 单实例 CLI | `--portable` / `--next` / `--quit` | 可被脚本、快捷方式、自动化工具驱动 |
| 工程可维护性 | 静态自检 `check_sources.py`、变更日志校验 `check_changelog.py`、日志首行带版本与环境 | 长期迭代的基础，不是卖点但决定能走多远 |

### 5.2 不对抗的方向

- **不做内容生态**：与 Steam 创意工坊对抗没有胜算。
- **不做创作者工具**：场景/粒子编辑器是团队级投入，收益集中在少数创作者。
- **不做移动端**：Wallpaper Engine 的 Android 伴侣是买断赠品，WallDesk 没有分发渠道优势。

## 6. 升级计划

排序依据：**（对日常体验的改善 × 竞品对齐紧迫度）÷ 实现成本**。P0 都是"成本低、直接补短板"的项。

### P0 —— v4.9（建议 1–2 个迭代内完成）

| # | 项目 | 为什么现在做 | 做法 | 成本 | 验收口径 |
|---|---|---|---|---|---|
| P0-1 | **逐应用暂停规则**（已落地） | 与 WE / Lively 差距最明显，且是「资源占用」这一核心诉求的直接答案 | 规则表存「可执行名 → 暂停 / 忽略」，复用 `FullscreenGuard` 的前台进程探测；设置页「播放」新增「资源控制」分组（列表 + 增删 + 双击切换）。**「停止（释放解码器）」未做**：需重建媒体并续播，留待 P1 | 中 | 给 `notepad.exe` 配「暂停」并切到它，日志出现 `应用规则命中：notepad.exe → 暂停壁纸`；再配「忽略」，全屏时不再暂停 |
| P0-2 | **档位可验证 + 省电档**（已落地） | 档位本来就有，缺的是「怎么确认它生效」 | 日志回显所选档位与下发的 libVLC 参数；新增「省电（限制解码线程）」档。**帧率上限未做**：libVLC 无原生限帧，需自定义 vout，代价高，留待评估 | 低 | 切换五档后日志各出现对应参数行（如 `--avcodec-threads=2`） |
| P0-3 | **触发规则**（已落地，形态有调整） | 现有「切换策略 + 定时场景」是两套孤立机制，且缺少「启动某应用时切换」这一触发条件 | 落地为「程序进入前台 → 套用场景预设」，复用已有预设对象与前台进程探测（2.5 s 轮询，只在程序切换时判定一次）。**未做**完整的「播放列表对象」**（条目 + 单项时长 + 拖拽排序）**：那需要新对象模型并迁移现有配置，收益主要是编辑器体验，评估后放在 P1 | 中 | 配置 `notepad.exe → 某预设` 后切到记事本，日志出现 `触发规则命中：notepad.exe → 应用预设「…」`（缺失预设时给出警告） |
| P0-4 | **卡片动态预览**（已落地，形态有调整） | 用户第一眼感知的差距；竞品全有 | 落地为「悬停 0.45 s 后用同一个离线实例连抓 8 帧（约 5 fps）循环播放」，复用串行视频池、不并发实例。**未做成**「静音播放 3 秒」：那需要把视频渲染进卡片（每个卡片一个宿主窗口），与现有 WorkerW 桌面层架构冲突面大，且悬停越界/滚动时窗口生命周期容易漏 | 中 | 悬停任一视频卡片 3 s 内出现循环画面；移开后停止解码；同一卡片回悬停立即播放（命中内存缓存） |
| P0-5 | **RDP / 会话切换暂停**（已落地） | Lively 已有；远程办公场景下省 GPU 与带宽 | 在 `DesktopWatcher` 处理 `WTS_REMOTE_CONNECT` / `WTS_REMOTE_DISCONNECT`，接入聚合后的暂停策略；启动时用 `SM_REMOTESESSION` 补齐初始状态 | 低 | 远程连接/断开时日志各出现一条记录，壁纸随之中断与恢复 |

| P1-2 | **壁纸包格式 `.wdpkg` + 导入导出** | 让"预设"升级为"可分享资产"，是内容生态的**替代方案** | zip + `manifest.json`（版本、类型、预览图、参数）；导入时校验版本与文件哈希 | 中 |
| P1-3 | **兼容 Lively ZIP 的视频/图片子集** | 直接借用对手的存量内容，成本远低于自建社区 | 解析 `LivelyInfo.json`，仅处理 Video/Gif/Image 类型，其它类型明确提示"不支持" | 中 |
| P1-4 | **网页壁纸（WebView2，可选组件）** | 品类分水岭，需单独决策：装上就多一个依赖面 | 以**可选组件**形式提供（首次启用时下载/检测 Edge WebView2 运行时），不打包进主安装包 | 高 |
| P1-5 | **多屏视频独立播放（可选开关）** | 当前单实例是为控内存，但多屏用户会认为"功能缺失" | 开关式：每个显示器一个 libvlc 实例；开启时给出内存占用提示，并提供"仅主屏有声"选项 | 中 |
| P1-6 | **屏幕保护接管** | WE 已有；实现独立于主程序，风险低 | 注册 `.scr` 入口，`/s` 复用当前壁纸全屏播放，`/c` 打开设置 | 中 |
| P1-7 | **在线源扩展** | 现有只有 Bing 一张/天，内容供给太少 | 接入 Wallhaven / Unsplash / Pexels 的公开 API（只读、需用户自填 key），支持关键词订阅与自动轮换 | 低–中 |

### 6.1 UI / 动效专项（跨版本，工作量小但感知强）

1. 页面切换与子页展开加 120–180 ms 缓动（`QPropertyAnimation`），不要弹性过冲。
2. 缩略图加载用淡入（`QGraphicsOpacityEffect`），替代当前的硬出现。
3. 首启动三步引导：添加壁纸 → 选填充方式 → 完成（可直接预置一张示例图，避免"打开是空的"）。
4. 拖拽导入：从资源管理器拖文件/文件夹到画廊即入库，并显示投放高亮。
5. 状态胶囊：主界面右下角显示「解码器 / 分辨率 / 帧率 / 内存」，点击展开详情（兼作 P0-2 的验证入口）。

### 6.2 性能专项

1. **渲染路径复查**：当前 `libvlc_media_player_set_hwnd_` 走窗口渲染（`VlcPlayer.cpp:361`），
   在高分屏 + 多屏下可能多一次拷贝。P1 阶段评估 libvlc 的视频回调 / D3D11 纹理共享路径，先做基准测量再改。
2. **空闲降帧**：无鼠标移动、无音频、无焦点变化超过 N 秒后降到 15 fps；有输入立即恢复。
3. **图片特效移出调用线程**：现状是 `WallpaperEngine.cpp:92` 直接同步调用 `ImageEffects::apply()`
   并 `save(cache, "PNG")`，逐像素处理跑在调用线程上，大图或大模糊半径会阻塞 UI。
   建议拆到 `QThreadPool` 按行分块，并顺带把缓存格式换掉（见下条）。
4. **缩略图缓存格式**：PNG → WebP（体积约降一半，磁盘缓存命中更快）。
